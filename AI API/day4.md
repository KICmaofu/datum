# 提示词进阶三大核心：角色设定｜格式约束｜思维链（CoT）引导
承接前面大模型API调用、多轮对话内容，下面包含原理、模板、可直接丢进API测试的示例，配套Python调用示例。

## 一、角色设定（Persona）
### 原理
给模型固定身份、背景、说话风格、知识边界，**限定输出视角**，避免模型泛泛而谈。
> 要点：不能只写“你是专家”，要写清楚：身份 + 能力范围 + 禁止行为 + 语言风格

✅ 优质角色模板
```
【角色】你是资深AI应用开发工程师，擅长大模型API落地、提示词工程。
【能力】讲解通俗易懂，附带代码示例；不编造不存在的模型参数。
【风格】回答分点，代码带注释；不知道的内容直接说明，不要臆测。
【禁止】不要长篇空话，不要使用夸张修辞。
```

❌ 劣质：`你是专家，回答我的问题`（信息太少，模型输出不稳定）

## 二、格式约束（Format Constraint）
### 原理
强制模型输出固定结构：JSON / Markdown表格 / 列表，方便后端直接解析，**是API工程化最常用技巧**。
> 重点：必须明确：输出格式 + 字段定义 + 禁止多余文字（防止模型加解释文本导致JSON解析失败）

✅ JSON格式示例（适合程序读取）
```
任务：分析用户提问。
输出严格遵守JSON，不要任何前置说明、结束语、注释。
字段：
- title：一句话总结问题
- keywords：数组，关键词
- difficulty：难度，可选值：简单/中等/困难
```
示例输出：
```json
{"title":"学习提示词进阶技巧","keywords":["角色设定","格式约束","思维链"],"difficulty":"中等"}
```

✅ Markdown表格示例（适合前端展示）
```
输出结果使用Markdown表格，仅保留表格，不要额外文字。
表头：技巧名称 | 作用 | 使用场景
```

## 三、思维链引导 CoT（Chain-of-Thought）
### 原理
让模型**先分步推理，再给出答案**。复杂推理类问题（计算、逻辑、方案设计）效果提升巨大。
两种写法：
1. **显式CoT**：直接要求“一步步思考”
2. **Few-shot CoT**：给1~2个推理示例，让模型模仿思考流程

✅ 显式CoT模板
```
请一步步思考，先写出推理过程，最后给出最终结论。
思考过程拆分成多个小点，不要跳步。
问题：xxx
```

✅ Few-shot CoT示例
```
示例1：
问题：10个苹果分给2个人，A比B多2个，B有几个？
思考：
1. 总数10，A=B+2
2. B + (B+2) =10 → 2B=8
3. B=4
答案：4

现在回答下面问题，和上面格式保持一致：
问题：xxx
```

> 注意：CoT会增加token消耗，简单问答场景**不需要开启**，会浪费成本。

# 组合完整版提示词（角色+格式+CoT，可直接用于API）
```
【角色】你是AI应用开发讲师，负责讲解大模型提示词工程。
【规则】
1. 复杂问题使用思维链分步推理，先思考，再总结答案；简单问题可直接回答。
2. 输出使用Markdown格式，分【推理过程】【最终答案】两块。
3. 不要多余闲聊，输出简洁专业。

问题：对比单轮对话和多轮对话API实现的优缺点。
```

# Python 调用示例（把上面组合提示词传入，复用之前多轮对话结构）
```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.getenv("LLM_API_KEY"),
    base_url="https://openai-compatible-endpoint"
)

messages = [
    {
        "role": "system",
        "content": """【角色】你是AI应用开发讲师，负责讲解大模型提示词工程。
【规则】
1. 复杂问题使用思维链分步推理，先思考，再总结答案；简单问题可直接回答。
2. 输出使用Markdown格式，分【推理过程】【最终答案】两块。
3. 不要多余闲聊，输出简洁专业。"""
    },
    {"role": "user", "content": "对比单轮对话和多轮对话API实现的优缺点。"}
]

resp = client.chat.completions.create(
    model="gpt-4o-mini",
    temperature=0.7,
    top_p=0.9,
    messages=messages
)

print(resp.choices[0].message.content)
```

# 实战避坑清单
1. **角色设定不要冲突**：同时设定“严谨科学家”和“幽默段子手”会导致输出不稳定
2. **JSON格式约束：一定要写禁止额外文字**，模型很容易额外加一句“下面是结果”导致json.loads报错
3. **CoT对创意写作用处不大**，推理类任务（逻辑、数学、方案拆解）收益最高
4. system消息承载角色+格式+CoT规则；user消息放用户当前问题，是工程最佳实践
